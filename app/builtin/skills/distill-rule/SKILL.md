# 从会话提炼 Rule

## 输入

用户引用了若干会话记录（`runs/<id>/*.md`），其中 `## User` 是用户的输入，`## Assistant` 是助手的回复和工具调用。工具调用后的 `→ failed` 带报错摘录，`→ rejected by the user` 后的 `>` 是用户拒绝的理由，`_(interrupted by the user)_` 是用户打断——这些往往就是用户的纠正。

## 步骤

1. 读 `library/README.md`，再读 `library/rules/` 下已有的规则，避免重复或冲突；有冲突时以新会话为准并在回复中指出。
2. 读完所有被引用的会话，重点找：
   - 用户**纠正**助手的地方（“不要……”“应该……”“我说的是……”）；
   - 用户拒绝或打断助手的地方，以及拒绝时说的理由；
   - 用户反复提出的要求（代码风格、语言、提交方式、测试方式、沟通方式）；
   - 项目或工具链的硬性约束（版本、目录、禁止改动的范围）。
3. 每个主题写一个文件 `library/rules/<name>.md`：
   - front matter：`name`、`description`；只对某些文件生效的规则，可加 `paths:`（glob 列表，Claude Code 会按路径加载）。
   - 正文：每条规则一行祈使句，必要时在下一行用“原因：”说明为什么；不要写空泛的原则。
   - 只写有会话依据的规则；只出现一次、明显是临时要求的不要写。
4. 用用户使用的语言写作。

## 结束

列出新建或修改的文件和其中的规则数量。
